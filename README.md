# PSA10高騰ランキング クラウド版

Macを起動していなくても、GitHub Actionsが毎日07:10（JST）ごろに
SNKRDUNKのPSA10相場を取得し、GitHub PagesでiPhoneから閲覧できます。

初回セットアップ:
1. ファイルをリポジトリのmainブランチへアップロード
2. Settings → Pages → SourceをGitHub Actionsに設定
3. Actions → Update PSA10 Rankings → Run workflowを実行
4. 完了後、公開URLをiPhoneで開く

注意:
- GitHub Actionsの定期実行は混雑時に遅れることがあります。
- SNKRDUNK側の画面構造が変わった場合、取得ロジック調整が必要です。
- 個人利用・低頻度アクセスを前提としています。


## 画面からカードを追加

1. ランキング画面の「＋カードを追加」を開き、SNKRDUNKの商品URLを貼り付けます。
2. 「GitHubで追加を確定する」で移動し、GitHubにログインして「Create」を押します。
3. ActionsがURLを検証し、cards.csvに重複なく登録して相場を取得・公開します。結果はIssueに記録されます。

所有者と書き込み権限のある共同管理者のみ自動登録できます。入力はHTTPSのsnkrdunk.com（wwwも可）の/apparels/数字に限定し、末尾のスラッシュ・共有用クエリ・フラグメントを除去します。ブラウザにGitHubトークンは保存しません。GitHub Actionsの一時トークンだけを使用します。

取得に失敗した申請は開いたまま残り、毎日の更新時に再試行します。URLが不正な場合はIssue本文を修正してください。既存のURLは追加し直しません。未処理Issueを毎回読み直すので、複数申請や待機中の実行の置き換えがあっても次回に回収できます。

### 公開設定

Settings → Pages → Build and deployment → Source を **GitHub Actions** に設定します。更新ワークフローがdocsを直接公開するため、ActionsのコミットでPagesが再構築されない問題を回避します。Actions → Update PSA10 Rankings → Run workflow で手動再実行できます。

毎日07:10 JSTのスケジュールは維持しています。履歴ファイルはdata/history.csvとdocs/history.csvです。直近比は最新相場のひとつ前、7日・30日・3か月・6か月は基準日以前の直近日を比較します。比較日の相場がない場合は「-」になります。

検証: `python -m unittest discover -s tests -v`

## 現在のPSA10総額・期間比較

現在総額は、価格取得済みの各カードの最新価格に保有枚数を掛けて合計します。

総額専用の切替で「直近比」「7日前」「30日前」「3か月前」「6か月前」を選べます。
- 直近比：各カードの相場日（source_date）順で、最新のひとつ前の価格。
- 7日前・30日前：各カードの最新相場日から7日・30日前を基準日とします。
- 3か月前・6か月前：各カードの最新相場日から暦で3か月・6か月前。同じ日がなければその月の末日（例：5月31日 → 2月28日、うるう年は29日）。
- 日付指定の比較は基準日ちょうどの価格を優先し、なければその日以前でもっとも近い相場日の価格を使用します。基準日より後の価格で代用しません。個別カードには実際に使用した比較元の相場日を表示します。

比較価格があるカードだけで現在側・比較側を同じ現在の保有枚数で加重して合計し、差額と「差額 ÷ 比較元合計」の率を算出します。保有枚数ベースの比較対象枚数・全枚数・除外枚数・両合計を表示します。履歴不足でも現在総額には含めます。比較対象0枚なら比較不可、比較元合計0円なら率は算出不可と表示します。

履歴は相場日ごとに保存されるため、直近比は前回の自動取得実行時点との比較ではありません。個別カードランキングの期間・並び順切替とは独立しています。取得処理・毎日07:10 JSTの更新・カード追加処理は維持しています。

### 個別カードの保有枚数

枚数は `cards.csv` の `quantity` 列で保存し、公開時に `docs/cards.csv` へコピーします。初回は原則1枚、従来2枚だった3種類は2枚を維持します。新規追加は1枚、既存URLの再追加では枚数を変更しません。

## iPhoneで所持枚数を変更

1. ランキングの「所持カード管理（枚数を変更）」を開きます。
2. 対象カードの「現在」の枚数を確認します。
   - 1枚減らす：「−」を1回押します。
   - 全部手放した：数字の欄に「0」を入力します。
   - 再購入した：「＋」を押すか、変更後の合計枚数を入力します。
3. 「この枚数でGitHubへ →」を押し、移動先で内容を確認して「Create」を押します（GitHubログインが必要）。
4. 数分後、Issueの完了コメントを確認し、ランキングを再読み込みします。

数字を変えただけでは保存されません。反映前に続けて変更する場合も、増減数ではなく最終的な合計枚数を申請してください。0〜9999枚を指定できます。

0枚は「未所持」となり総額・全比較から除外します。カード登録・過去相場は削除せず、毎朝の相場取得も続けます。1枚以上に戻すと既存の履歴ですぐ比較できます。すべて未所持なら総額は0円です。相場未取得カードも管理画面に表示しますが、その評価額は総額に含めず除外種類数を表示します。

個別ランキングは1枚あたりの相場変動順のままです。所持枚数0のカードは一覧に表示せず、1枚以上に戻して公開後に再読み込みすると自動的に再表示します。未所持カードも所持カード管理には残ります。総額の比較元にも現在の枚数を掛けます。過去に実際に持っていた枚数での資産推移ではありません。

変更は追加と同じIssue/Actions経由です。Actionsで申請者の現在の書き込み権限を確認します。ブラウザに秘密情報は保存しません。処理済み申請の識別子を `data/holding_requests.json` に枚数と同時に保存するため、公開・通知の失敗後の再実行で古い申請が新しい枚数を上書きしません。変更結果はPages公開成功後に通知され、相場取得が失敗しても既存相場で枚数変更を公開できます。

総額の検証: `node --test tests/test_portfolio.cjs`

個別ランキングも「直近比｜7日前｜30日前｜3か月前｜6か月前」から選択できます。比較不可は「-」とし、選択した指標で比較可能なカードの後に表示します。iPhoneではラベル付きの48px以上の期間選択を使えます。


### 枚数変更の処理状況

`[所持枚数]` Issueの作成・編集・再オープンでActionsが自動実行されます。書き込み権限・入力を確認後、受付コメントを表示し、公開成功後に完了コメントと自動Closeを行います。

所持枚数の申請だけの場合、相場の再取得を省いて既存の相場と新しい枚数を公開します。同時に未処理のカード追加があれば、従来どおり相場を取得します。毎朝07:10 JST・手動実行・コード更新時の相場更新も維持しています。

実行中の更新がある場合は順番待ちになります。連続申請では待機中のActionsが置き換わる場合がありますが、実行時に未処理Issueをすべて確認するため申請は失われません。受付コメントのActionsリンクで進行状況を確認できます。
